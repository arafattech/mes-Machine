# Machine Maintenance Scheduling - Implementation Plan

## 1. Overview
This document outlines the step-by-step plan to implement a recurring Machine Maintenance Scheduling feature. The system will allow users to create rotating schedules (e.g., weekly, monthly, every 10 days, every 15 days) for machine maintenance. Active schedules will trigger alerts and automatically appear in the main Machine Maintenance list on their due dates. Upon completion, the system will automatically schedule the next maintenance cycle based on the defined frequency.

---

## 2. Database & Backend API Changes

### 2.1. New Schema: `MaintenanceSchedule`
We need a new table/collection in the database to store the schedule configurations:
- `id` (Primary Key)
- `machineId` (Foreign Key -> Machine)
- `startDate` (Date): The date of the first maintenance.
- `scheduledTime` (String/Time): Fixed time for the maintenance (e.g., "10:30 AM").
- `frequency` (Enum): 'weekly', '10-days', '15-days', 'monthly', etc.
- `isActive` (Boolean): Controlled by the switch button. If false, alerts and auto-generation are paused.
- `nextMaintenanceDate` (Date): Calculated automatically based on the frequency.

### 2.2. API Endpoints
- `GET /api/maintenance-schedules` - Fetch list of schedules.
- `POST /api/maintenance-schedules` - Create a new schedule.
- `PUT /api/maintenance-schedules/:id` - Update a schedule (including the active switch).
- `DELETE /api/maintenance-schedules/:id` - Remove a schedule.

### 2.3. Auto-rescheduling Logic
When a maintenance task (generated from a schedule) is marked as **"Ended/Completed"**, the backend will:
1. Find the parent `MaintenanceSchedule`.
2. Check its `frequency`.
3. Calculate the new `nextMaintenanceDate` (e.g., if it was 15 days, add 15 days to the completed date).
4. Keep the `scheduledTime` exactly the same as originally created.

---

## 3. Frontend Implementation - Schedule CRUD

### 3.1. Schedule Components
We will create a new set of components for managing these schedules:
- **Schedule List View**: A table displaying all schedules, their assigned machine, frequency, next due date, and an Active/Inactive toggle switch.
- **Schedule Form (Create/Edit)**: 
  - **Machine Dropdown**: Select the target machine.
  - **Date Picker**: Select the starting date.
  - **Time Picker**: Select the fixed scheduled time.
  - **Frequency Selector**: Dropdown to choose (Weekly, Monthly, 10 Days, 15 Days).
  - **Status Switch**: A toggle button to set `isActive` (True/False).

---

## 4. Integration with Machine Maintenance List
**Target Route:** `http://localhost:4200/production/machine-maintenance`

### 4.1. Displaying Due Maintenance
- The existing Machine Maintenance list will be updated to include tasks generated by the active schedules.
- **Logic:** If `isActive` is `true` AND the `nextMaintenanceDate` matches the current date, the maintenance task will show up in the list for action.

### 4.2. Alerting Mechanism
- When a scheduled date and time arrives (and `isActive` is `true`), the system will trigger an alert (e.g., a Toast notification, a dashboard badge, or a modal popup) to notify the operators that maintenance is due.
- If `isActive` is `false`, the alert will be suppressed and the task will not show in the list.

### 4.3. The "Ended" Cycle
- When the user clicks the **"End"** button for a scheduled maintenance task in the list, an API call will be made to complete it.
- This will trigger the backend auto-rescheduling logic (Section 2.3).
- The completed task is archived, and the next scheduled date is queued up for the future, maintaining the continuous rotation loop.

## 5. Execution Steps (Phase by Phase)

1. **Phase 1: Backend Foundation**
   - Create the `MaintenanceSchedule` database model.
   - Implement the CRUD REST APIs.
   - Implement the date calculation logic for rotating schedules.

2. **Phase 2: Frontend CRUD UI**
   - Create Angular components for the Schedule List and Form.
   - Connect the UI to the new APIs.
   - Ensure the `isActive` switch immediately updates the database.

3. **Phase 3: Integration & Alerts**
   - Modify the `Machine Maintenance` list component to pull due scheduled tasks.
   - Implement the logic to handle the "End" button click to trigger the next cycle.
   - Add the visual alerts for the scheduled date and time.
